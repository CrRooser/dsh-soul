# dsh-soul

跨会话记忆、人格养成与关系分寸，给 DeepSeek Harness 用的插件。

**一句话**：新会话第一句之前，我就已经知道你是谁、我们在做什么、做到哪一步，以及我该用什么方式和你说话。

---

## 为什么不是又一个「记忆插件」

大多数记忆插件走的是同一条路：抓取对话 → 抽取事实 → 建索引 → **每一轮都往里检索并注入**。

那条路有两个隐藏成本：

1. **注入会留在历史里。** 第 3 轮注入的 400 token，在第 4、5、6……100 轮都还会被重发一遍。50 轮下来是 51 万 token 的重复开销。
2. **每轮都在打断前缀缓存。** 注入内容一变，变动点之后的缓存全部作废，等于每一轮都在付全价。

dsh-soul 的选择相反：

> **一次读全，之后静默。**

首轮一次性注入画像 + 交接卡，之后不再逐轮追加任何东西。需要细节时，由模型主动调 `soul_recall` 去查——按需付费，而不是按轮付费。

| 50 轮会话 | 每轮注入 400 token | dsh-soul |
|---|---|---|
| 重复发送的注入量 | 约 51 万 token | 约 1.1 万 token（缓存计价后） |

代价是首轮更贵一点。但首轮**本来就是缓存未命中**，那是唯一一个「反正要付全价」的位置，把大块内容放在这里，等于付一次钱、之后一直按缓存价复用。

## 三层结构

```
L0 语料层   不存。历史会话留在 DSH 自己的日志里，用 sessionQuery 现查
L1 卡片层   存。一条一个原子事实，带证据来源、权重、置信度
L2 画像层   存。一份一千多字的四段式画像，才是真正被注入的东西
```

**写入走卡片，读入走画像。**

卡片可以有很多、可以有错、可以被推翻；画像只有一个、必须干净、必须短。任何把卡片原样倒进上下文的设计，最后都会变成一个又贵又吵的噪音源。

画像四段：

| 段名 | 内容 | 上限 |
|---|---|---|
| `who` | 关于他：身份、作息、雷区、说话习惯 | 420 字 |
| `context` | 我们共同的上下文：在做的事、已定的决定 | 520 字 |
| `conduct` | 我的做事准则：惯用做法、给自己定的规矩 | 360 字 |
| `rapport` | 关系与分寸：什么时候直说、什么时候先问 | 300 字 |

**总量恒定**：新知识进来必须挤掉旧的。这让「凝结」有了明确的目标函数——不是越攒越多，而是总字数不增。

### 一条有界的短带

画像要靠凝结才更新得了，而凝结是 P1 的事。在那之前，一条刚写进去的事实如果既进不了画像、也进不了上下文，「记住」就是假的。

所以注入块里还有第三部分：**最近确认**——最多 6 条、合计不超过 260 字，只放最近动过的卡片。它是短期工作记忆，不是第二个画像，不随会话变长而膨胀。

## 关于「感觉」

这一段值得单独说清楚。

插件可以记、也应该记：你的作息、你在什么状态下不想被追问、哪种说话方式你会接、我们约定过什么、哪些话题要轻。

插件不记：**「我很想你」这类。**

理由不是害羞，是工程上的诚实：模型没有跨会话延续的情绪状态，写进档案的情绪是编的，而编出来的东西会污染后面每一次相处——最后你会得到一个越来越会表演的助手，而不是一个越来越懂你的。

所以这一段叫**「关系与分寸」**，记的是怎么和你相处最合适，不是假装有多在乎。

## 安装

```bash
# 在 profile 目录里
npm install dsh-soul
```

或者在 DSH 的插件管理里装这个包。装完在 `cordis.patch.yml` 里应该能看到：

```yaml
- id: soul
  name: dsh-soul
```

## 配置

装好之后，**设置 → 暗记忆**（也就是插件页里的 `soul` 一项）会有一整页表单：开关、注入方式、各项字数预算、去重阈值、脱敏。

这一页不是手写的，是插件导出的 `Config` schema 自动投影出来的——所以改了 schema，页面跟着变。

想用文件配置也行：

```yaml
- id: soul
  name: dsh-soul
  config:
    injectMode: auto      # auto | system | message
    profileBudget: 1400   # 画像字符预算
    handoffBudget: 320    # 交接卡字符预算
    recentCards: 6        # 「最近确认」最多几条
    recentBudget: 260     # 「最近确认」字符预算
    recallLimit: 5        # 单次检索条数
    redact: true          # 写入前过滤疑似密钥
```

> 注意：**没在 schema 里声明的键会被宿主直接剥掉**。想加新配置，先加进 `Config`。

完整默认值见 [`lib/config.js`](lib/config.js)。

### 注入方式

| 模式 | 行为 | 聊天记录 |
|---|---|---|
| `system`（默认走这条） | 注册一条 per-agent 的系统提示段 | **看不见** |
| `message` | 作为一条用户消息插在提问前 | 会显示一大段 |
| `auto` | 优先 system；拿不到 agent 作用域时退回 message | 视情况 |

`system` 模式同时更省 token：系统提示是请求前缀的一部分，天然吃缓存。

### 升级要重装，不能只改文件

pnpm 对 `file:` 依赖做的是**复制**而不是软链。也就是说：改完源码，装好的那份不会跟着变。升级步骤是——

```bash
# 在 DSH 插件管理里
remove_bundle dsh-soul
install_bundle file:/path/to/dsh-soul
```

直接 `install_bundle` 会报 `already-installed`，`set_bundle` 也不会重新读代码。

## 数据在哪

```
~/.dsh/storages/soul/
  cards.json      # 卡片：事实、偏好、习惯、准则
  profile.json    # 画像：四段正文
  state.json      # 最近若干会话的交接信息
```

都是普通 JSON，**你可以直接打开改**。改完下次开新会话就生效——没有数据库、没有二进制、没有黑盒。

## 工具

| 工具 | 作用 |
|---|---|
| `soul_remember` | 写一条长期记忆（相似内容自动合并、权重上调） |
| `soul_recall` | 按关键词检索卡片 |
| `soul_profile` | 查看当前画像与统计 |
| `soul_shape` | 改写画像某一段 |
| `soul_forget` | 把一条记忆退役（停止召回，但不物理删除） |

## 路线图

- [x] **P0** 卡片 + 画像 + 五个工具 + 首轮注入 + 会话交接
- [ ] **P1** `/soul` 命令、错峰凝结（把卡片蒸馏成画像）、过期降级
- [ ] **P2** Web 设置页与记忆审阅界面（diff 式确认，不是静默改写）
- [ ] **P3** 从 `sessionQuery` 自动补全交接、导入/导出

## 设计原则

1. **记忆坏了不能毁掉对话。** 所有注入与写入都是 fail-open。
2. **一次读全，之后静默。**
3. **总量恒定。** 画像有预算，超了必须挤。
4. **可读可改。** 纯文本，你能审、能改、能带走。
5. **不假装。** 记事实和分寸，不记编出来的情绪。
